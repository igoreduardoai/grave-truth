# Idea evaluation

Use this before building. It is a worksheet, not evidence that anyone wants the thing, will pay for it, or that a sponsor will prize it. Another pass has to find the actual ideas. Do not start a product from a guess written here.

## Observed pain

What was seen, where, and by whom. A quote, a ticket, or a session note. If this box is a hypothesis, write "hypothesis" and stop treating it as demand.

## Current workaround

What people do today, in steps. If nobody was observed, write "not observed."

## Alternatives and what would be new

Name the closest existing tools. Say what this would do that those do not. A search with no notes is not a novelty check.

## Sponsor critical path

Which published rule or category this would have to satisfy. Link the rule. Mark the check manual unless a person verified the text against that rule. Do not assume a project is new, eligible, or inside a category.

## Visible task in a demo

One task a viewer can watch finish on screen. What they see at the end. What would make that ending surprising rather than a labeled dashboard.

## Feasibility, cost, risk

What has to be true to build it. Money, data, accounts, and review. What happens if the source text is wrong or hostile.

## Falsifiable test

The observation that would show the idea failed. Where the evidence will be stored. The denominator. A persona run is not this test, and it does not show desire or willingness to pay.
